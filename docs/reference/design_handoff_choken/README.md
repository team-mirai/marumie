# Handoff: 調査研究費（調研費）機能

marumie に「調査研究費」機能を追加するための実装ハンドオフ。公開側（webapp）と管理側（admin）の両方を含む。

## Overview

調査研究費（国会議員に毎月100万円支給される公費）を、議員単位で1件ずつ領収書つきで公開する機能。

- **公開側（webapp）**: 政党ページへの調研費サマリー追加（A-6）と、議員ページ（B-1〜B-5：サンキー・月次推移・主要な支出の成果・全支出テーブル・データについて）
- **管理側（admin）**: スキャンベースの入力パイプライン。領収書画像/PDF を一括アップロード → Claude（vercel ai 経由）で構造化 → 下書き仕訳 → 人間の目視確認 → サンキー before/after を見て公開

データは**複式簿記**で保持する（journal_entries + journal_lines）。公開側は published な仕訳の費用行を射影した単式ビュー。

## About the Design Files

`design/` 配下のファイルは **HTML で作られたデザインリファレンス**（プロトタイプ）であり、そのまま本番に載せるコードではない。タスクは、これらのデザインを marumie の既存環境（Next.js 16 App Router / Tailwind / shadcn 風 ui コンポーネント / Bounded Context アーキテクチャ）で**再現実装**すること。

- HTML はブラウザで直接開ける（`design/調研費 管理画面.dc.html` など）。すべて動くプロトタイプで、画面遷移・状態変化・キーボード操作も実装済み
- このフォルダごと `docs/reference/design_handoff_choken/` としてリポジトリにコミットして、ループの参照物にすることを推奨（`docs/reference/design_handoff_admin_redesign/` と同じ扱い）

## Fidelity

**High-fidelity（hifi）**。admin は実リポジトリの `admin/src/app/globals.css`・`docs/admin-ui-guidelines.md`・実コンポーネント（PageHeader / Button / Table / CategoryPill 等）の実装を読み込んだうえで、そのトークン・形状に揃えて作ってある。webapp 側も本番サイトのスタイルに準拠。**再実装時は必ずコードベース側の既存コンポーネントを使い、プロトタイプの inline style を移植しないこと。**

## 実装順序

ユーザー方針により**バックエンドをおよそ作りきってからフロントエンド**を作る：

1. **Phase 0**: Prisma schema（`loop:human` — マイグレーションはループに実装させない運用ルールのため）、Supabase Storage・環境変数（人間）
2. **Phase 1**: バックエンド（research-fund コンテキスト）。Done はユニットテストで検証
3. **Phase 2**: admin フロントエンド（画面ごとに1 Issue、Phase 1 の usecase を配線）
4. **Phase 3**: webapp 公開ページ

repo の原則は「1 Issue = 縦切り（server / client で分割しない）」だが、本件は新規コンテキストの立ち上げでバックエンドの土台が大きいため、**Phase 1 は Done をテストで検証できる形に切った横切り**、Phase 2 以降で縦に繋ぐ構成にしている。詳細と各 Issue の Done / Out of scope は `04_ループIssue一覧.md`。

## 主要な設計決定（確定済み）

ユーザーヒアリングで確定した事項。実装時に蒸し返さないこと：

1. **複式簿記**でデータ保持。ただし管理画面 UI は**科目＋金額のみ表示**（借方/貸方は裏側で自動生成。仕訳パターンは3つだけ：支出・支給・年度末返還）
2. 仕訳ステータスは **draft → approved → published の3段階**。スキャン直後は draft、人間の確認で approved、公開画面で published
3. 目視確認 UI は**一覧表＋右パネル**（選択行の領収書と抽出結果を並べ、↑↓キーで次へ）
4. 領収書は**当面マスキングなしで原本公開**（`masked_key` カラムだけ用意）
5. プロンプト管理は**版履歴＋巻き戻し＋テスト実行**（1枚流して結果を見る、仕訳は作らない）。プロンプトは**自動生成部（出力スキーマ・21分類の語彙と定義文。コードが組み立て・編集不可・画面から折りたたみで参照可）＋議員室プロンプト（編集可能）**の2層で、split_group の分割粒度や「迷ったら needs-review」などのポリシーは固定部にせず議員室プロンプトの**デフォルトテンプレート**（初期版）に置く
6. 支出群の金額・件数・期間は**仕訳の紐づけから自動集計**（手入力しない）
7. 支給（毎月100万円）は**月ごとに1クリック生成**。下書きを経ず approved で作成
8. 利用者は**各議員室のスタッフ（自室の帳簿のみ）**。テナントは既存 auth に相乗り
9. 政党⇄議員の9. 議員の親は**既存の political_organizations**（政党テーブルは新設しない）。リレーションは**別テーブル（membership）**で、所属なしでも議員は存在できる
10. **グローバルセレクタ**：対象（政治団体×年度／議員×年度）をサイドバー上部で1箇所選択し、明示的に切り替えるまで変わらない。選択モードでサイドバーの中身が変わる。「ユーザー情報」ページは廃止、「政治団体」は政治団体モードのセクションに移動
11. 仕訳には**特記事項（note・公開される）**と**備考（memo・公開されない事務所内メモ）**の両方を持つ
12. 費用カテゴリは**ユーザー提供の調研費カテゴリ21分類**（定義・代表原文例つき）。旧ワイヤーの15分類は廃止（01_データモデル.md の表が正。プロトタイプ内の15分類表記はサンプル）
