# 01 データモデル（Prisma schema 草案）

既存の `prisma/schema.prisma` の慣習（snake_case テーブル・カラム、BigInt id、created_at/updated_at）に合わせること。**このファイルは草案であり、実装時は既存 schema の型・命名規約を正とする。** マイグレーションは `loop:human`（人間が内容と適用手順を確認する運用ルール）。

## 全体像

```
tenants ─< politicians >─ politician_org_memberships >─ political_organizations（既存・変更なし）
              │
              └─< research_fund_books（議員×年度＝1年間のお財布）
                     ├─< research_fund_journal_entries ─< research_fund_journal_lines（複式）
                     │        │ document_id?                    │ account_key
                     │        └─→ research_fund_documents      └─→ research_fund_accounts（固定マスタ）
                     ├─< research_fund_scan_batches ─< research_fund_scan_jobs（1書類=1ジョブ）
                     └─< research_fund_expenditure_groups ─< group_items / group_outcomes
politicians ─< research_fund_prompts（読み取りプロンプト・版管理）
```

既存 `transactions`（政治資金・freee複式）には**一切手を入れない**。counterpart/donor の DB トリガーが transactions の category_key 語彙に依存しているため、調研費は完全に別系統のテーブルにする。

## schema 草案

```prisma
// 政党テーブルは新設しない。親は既存の political_organizations を使う（変更なし）。
// 紐づけは membership に切り出すので、政党なしでも議員は存在できる。

model Politician {
  id            BigInt   @id @default(autoincrement())
  tenant_id     BigInt   // → tenants.id（既存 auth に相乗り）
  name          String
  slug          String   @unique
  term_start    DateTime @db.Date // 支給の起点（当選日）
  display_order Int      @default(0)
  memberships   PoliticianOrgMembership[]
  books         ResearchFundBook[]
  prompts       ResearchFundPrompt[]
  @@map("politicians")
}

model PoliticianOrgMembership {
  id                        BigInt    @id @default(autoincrement())
  politician_id             BigInt
  political_organization_id BigInt    // → political_organizations.id（既存）
  started_on                DateTime  @db.Date
  ended_on                  DateTime? @db.Date // 離党・移籍の履歴を残す
  @@map("politician_org_memberships")
}

enum ResearchFundBookStatus { preparing active closed }

model ResearchFundBook {
  id                BigInt   @id @default(autoincrement())
  politician_id     BigInt
  financial_year    Int
  status            ResearchFundBookStatus @default(preparing)
  published_through DateTime? @db.Date // 何月分まで公開（例: 2026-08-31）
  as_of_date        DateTime? @db.Date // 「2026.8.20時点」
  next_update_note  String?             // 「次回更新 11月ごろ」
  policy_comment    String?             // 活用方針（帳簿全体・議員本人が書く1〜2行）
  details           Json?               // B-5「データについて」の説明文
  @@unique([politician_id, financial_year])
  @@map("research_fund_books")
}

enum ResearchFundAccountType { asset income expense }

model ResearchFundAccount {
  key                String  @id // "taxi" など
  label              String  // "タクシー代"
  type               ResearchFundAccountType
  legal_category_key String? // 法定区分キー（expense のみ）
  legal_label        String? // "③ 備品・消耗品費"
  display_order      Int     @default(0)
  @@map("research_fund_accounts")
}

enum ResearchFundEntryStatus { draft approved published }
enum ResearchFundEntrySource { scan manual grant }

model ResearchFundJournalEntry {
  id           BigInt   @id @default(autoincrement())
  book_id      BigInt
  entry_date   DateTime @db.Date
  description  String   // 公開用の項目名（「タクシー代」。店名でなく何に使ったか）
  status       ResearchFundEntryStatus @default(draft)
  source       ResearchFundEntrySource
  document_id  BigInt?  // 領収書。manual で領収書を徴し難かった場合は NULL
  split_group  String?  // 同一注文の行分割キー（Amazon 3点購入 → 3仕訳を束ねる）
  note         String?  // 特記事項（公開される。為替換算・利用期間など）
  memo         String?  // 備考（公開されない。事務所内メモ）
  published_at DateTime?
  created_by   BigInt?  // → users.id
  hash         String   // 再取込・二重登録の重複検知（transactions の hash を踏襲）
  lines        ResearchFundJournalLine[]
  @@map("research_fund_journal_entries")
}

enum JournalSide { debit credit }

model ResearchFundJournalLine {
  id          BigInt @id @default(autoincrement())
  entry_id    BigInt
  side        JournalSide
  account_key String // → research_fund_accounts.key
  amount      Decimal @db.Decimal(12, 0) // 円・整数
  @@map("research_fund_journal_lines")
}

model ResearchFundDocument {
  id                BigInt  @id @default(autoincrement())
  book_id           BigInt
  batch_id          BigInt?
  storage_key       String  // Supabase Storage のキー（原本）
  masked_key        String? // 公開用マスキング済み（当面は未使用＝原本公開）
  mime              String  // image/jpeg | image/png | application/pdf
  original_filename String
  @@map("research_fund_documents")
}

model ResearchFundScanBatch {
  id          BigInt @id @default(autoincrement())
  book_id     BigInt
  uploaded_by BigInt // → users.id
  jobs        ResearchFundScanJob[]
  @@map("research_fund_scan_batches")
}

enum ScanJobStatus { queued running succeeded failed }

model ResearchFundScanJob {
  id          BigInt  @id @default(autoincrement())
  batch_id    BigInt
  document_id BigInt
  status      ScanJobStatus @default(queued)
  prompt_id   BigInt  // 使った版を記録（後から「どの版で読んだか」を追える）
  model       String  // "claude-opus-4-1" など
  raw_json    Json?   // LLM の構造化出力の原文（監査用）
  error       String?
  started_at  DateTime?
  finished_at DateTime?
  @@map("research_fund_scan_jobs")
}

model ResearchFundPrompt {
  id            BigInt  @id @default(autoincrement())
  politician_id BigInt  // 議員室ごと
  version       Int
  body          String
  is_active     Boolean @default(false)
  updated_by    BigInt? // → users.id
  @@unique([politician_id, version])
  @@map("research_fund_prompts")
}

model ResearchFundExpenditureGroup {
  id            BigInt @id @default(autoincrement())
  book_id       BigInt
  title         String
  description   String  // 使った目的と、そこから生まれたもの
  display_order Int     @default(0)
  items         ResearchFundGroupItem[]
  outcomes      ResearchFundGroupOutcome[]
  @@map("research_fund_expenditure_groups")
}

model ResearchFundGroupItem {
  group_id BigInt
  entry_id BigInt
  @@id([group_id, entry_id])
  @@map("research_fund_group_items")
}

model ResearchFundGroupOutcome {
  id            BigInt  @id @default(autoincrement())
  group_id      BigInt
  label         String  // "質問主意書（公開）" "議事録" など
  url           String? // NULL なら公開側で「報告は準備中」表示
  display_order Int     @default(0)
  @@map("research_fund_group_outcomes")
}
```

## 複式簿記の不変条件

- 仕訳ごとに **借方合計 = 貸方合計**。ドメイン層（`JournalPosting`）で検証し、違反は保存させない。DB 側の CHECK/トリガーは任意（counterpart トリガーの前例に倣うなら追加可）
- 仕訳パターンは3つに固定（UI は科目＋金額だけを見せ、lines はドメインが生成する）：

| パターン | source | 借方 | 貸方 |
|---|---|---|---|
| 支出 | scan / manual | 費用科目（15分類） | 普通預金（or 現金） |
| 支給 | grant | 普通預金 | 調査研究費収入 |
| 年度末返還（未使用） | manual（クローズ処理） | 調査研究費収入（返還） | 普通預金 |

## 公開側（webapp）への射影

公開ページが読むのは**単式ビュー**：

- 支出一覧（B-4）＝ `status=published` の entries × `side=debit` かつ `account.type=expense` の line。1行 = {entry_date, account(label/legal_label), description, amount, note, split_group, document(storage_key), receipt有無}
- 支給（B-1 左ノード・B-2 上向き棒）＝ `source=grant` かつ published の entries
- 未使用 ＝ 支給合計 − 支出合計（返還仕訳が入るまでは導出値）
- サンキー・月次・KPI はすべてこのビューからの集計。SQL VIEW にするか loader 内の集計にするかは実装判断（webapp は `unstable_cache` + tags、公開アクション側で revalidateTag）

## 旧設計との差分

- プロジェクト内の旧ドキュメント `調研費データモデル.dc.html`（単式の research_fund_transactions 案）は**本設計（複式）で置き換え済み**。grants テーブルも廃止し、支給は `source=grant` の仕訳に統一した
- **parties テーブルは新設しない**。議員の親は既存 `political_organizations` を membership 経由で参照する（デザインプロトタイプの「＋政党を新規作成」は既存の政治団体作成に読み替える）
- 費用カテゴリは旧ワイヤーの15分類から**ユーザー提供の21分類**に差し替え済み（上表）。プロトタイプ・旧ワイヤー内の15分類表記はサンプルとして読み替えること
