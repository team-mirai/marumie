# ドキュメントの読み方

このリポジトリのドキュメントは、**現行の正（正本）** と **作成時点のスナップショット** の2種類に分かれる。
どちらに属するかで信頼度がまったく違うため、**何かを調べる前にこのファイルを読むこと**。

## 分類基準

| 分類 | 置き場所 | 定義 | 扱い方 |
|------|---------|------|--------|
| **現行の正（正本）** | `docs/` 直下、`docs/reference/` | 現在のルール・仕様を規定し、変更のたびに更新される文書 | **現行の根拠にしてよい**。実装がここと食い違っていたら、実装かドキュメントのどちらかがバグなので指摘する |
| **作成時点のスナップショット** | `docs/old/` | 実装当時の設計メモ・要件定義。書かれた時点の記録であり、その後更新されない | **現行の根拠にしてはいけない**。経緯を知るための参考情報として読む |

## LLM・AIエージェント向けの読み方ルール

1. **現行の根拠にしてよいのは正本だけ。** `docs/old/` の記述を「現在こう実装されているはず」の根拠にしてはいけない。
2. **スナップショットの記述と実装が食い違ったら、実装が正。** `docs/old/` は書かれた時点の設計であり、その後の作り直し・廃止が反映されていない。実装を読んで判断すること。
3. **新しく書く設計ドキュメントは `docs/old/` に置く。** 設計メモ・要件定義・実装計画はすべてスナップショットである。ファイル名は既存の慣習にならい `YYYYMMDD_HHMM_タイトル.md` とする。
4. **正本を新設・更新したときは、このファイルの一覧も更新する。** ルールを規定する文書（ガイド・運用ルール）を追加する場合だけ `docs/` 直下に置く。
5. **リポジトリの作業ルールそのものは [../CLAUDE.md](../CLAUDE.md) を起点に探す。**

## 過去ドキュメントを消さない理由

`docs/old/` は「なぜこの設計になったか」を追うための履歴として残している。
古いという理由で削除せず、分類して読み分ける方針を取っている。
