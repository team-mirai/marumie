## 現在の状況

- 現在のブランチ: !`git branch --show-current`
- 変更ファイル: !`git diff --name-only HEAD~1 2>/dev/null || git diff --name-only --cached 2>/dev/null || git diff --name-only`

## タスク

以下の手順で現在のブランチの変更内容に対して設計レビューを行ってください：

1. **変更内容の把握**: `git diff` で変更されたファイルの差分を取得し、変更内容を把握する。必要に応じて関連ファイルも読み込む。

2. **ガイドラインの参照**: 変更対象に応じて以下のガイドラインを参照する。
   - `admin/src/server/contexts/` または `webapp/src/server/contexts/` 配下の変更: [docs/backend-architecture-guide.md](docs/backend-architecture-guide.md)
   - `admin/src/client/` または `admin/src/app/` 配下の変更: [docs/admin-ui-guidelines.md](docs/admin-ui-guidelines.md)

3. **レビュー実施**: 以下の観点でレビューを行う。
   - **アーキテクチャ**: ガイドラインに沿ったレイヤー構成・責務分離ができているか
   - **import パス**: `@/` から始まる絶対パスを使用しているか（相対パス禁止）
   - **型定義**: 適切な型が定義されているか
   - **命名**: 変数名・関数名・ファイル名が適切か
   - **ドメインモデル貧血**（[docs/backend-architecture-guide.md の 4.5](docs/backend-architecture-guide.md#45-ドメインモデル貧血)）:
     指摘の前に、差分の外にある同じコンテキストの `domain/`・`contexts/shared/domain/`・直下の `shared/` を検索して、同じルールが既にあるかを確かめる
     - usecase: 状態による操作の可否、業務上の検証、金額の計算・集計の定義、却下理由の文言を書いていないか（既にドメインにあるはずではないか）
     - action: ドメインの却下理由をエラーコードごとに別の文言へ書き直していないか。業務上の定数を自前のリテラルで持っていないか
     - リポジトリ実装: どの状態を対象にするか・どの行を数えるか・既定値を、検索条件や保存データの組み立てにだけ書いていないか
     - 画面（client / app）: 金額の定義・公開している年度・ボタンを出してよい条件を自前で計算・保持していないか
     - ドメイン: 追加した判定・検証が本番コードから呼ばれているか（テストだけが呼んでいないか）。型だけを足してルールを外に置いていないか
     - 同じ判定が別の層にもう一度書かれていないか
     - 取得・not found・同時更新の検出・永続化・キャッシュ無効化・入力の型や必須の検証・外部形式との機械的な変換・見た目の整形は貧血ではない
     - 判定の正はサーバー側。画面がドメインを呼んでいないこと、サーバーの却下理由を表示するだけであること、リポジトリの並び順をそのまま使うことは指摘しない
     - 逆に、貧血の解消だけを目的に API の形・画面の state・変換用の型を足している変更や、SQL の並び順・条件を TypeScript でもう一度実装している変更は、不要ではないかを指摘する

4. **結果報告**: 以下の形式でレビュー結果を報告する。重大な問題がない場合は「✅ 設計上の問題は見つかりませんでした」と報告する。

```
## レビュー結果

### ✅ 良い点
- ...

### ⚠️ 改善提案
- **[ファイル名:行番号]** 問題の説明
  - 提案: ...

### ❌ 要修正
- **[ファイル名:行番号]** 問題の説明
  - 理由: ...
  - 修正案: ...
```
